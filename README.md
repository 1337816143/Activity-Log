# 活动档案 · Activity Log

部门活动记录与附件资料库。原生 ES Modules + CSS + IndexedDB，无运行时第三方依赖。

## 核心功能

- 按条记录活动名称、活动时间、参与具体工作与人员，支持地点、分类、备注、星标及编辑删除。
- 全文查询及类型、人员、日期组合筛选；卡片、表格、时间线、附件库与人员统计。
- 多文件选择、拖放上传，原文件保留；图片、PDF、音视频及纯文本快速预览。
- 图片完整显示，后续卡片依次堆叠；滚轮、方向键、数字小键盘 8/2/4/6、拖动与触摸切换。
- 浅色 / 深色玻璃界面、响应式布局、减少动态效果支持。
- 完整备份包含记录及附件原文件；CSV 仅包含文字数据。

## 数据边界（重要）

这是 **本机资料库**，不是云端多人协作系统。实际记录和附件保存在当前设备、当前浏览器的 IndexedDB 中，不会自动上传到这个公开仓库。刷新或关闭页面不会主动删除记录；清理网站数据、无痕模式、浏览器存储压力或更换设备可能导致数据不可用。请定期导出完整备份。

没有账号登录、云端数据库、权限控制或自动跨设备同步。任何人访问站点都不会自动读到另一位使用者的本机资料；同一浏览器的使用者可以查看其资料。GitHub Pages 同一 `github.io` 源下的站点共享浏览器源，因此本机存储不构成独立的安全隔离边界。真正的部门多人共享应另接带身份验证、访问控制与私有对象存储的后端，不应把真实人员资料和附件提交到公开仓库。

示例记录全部虚构，插画为原创矢量示意，不代表真实活动，也不会自动写入个人资料库。无追踪器、外部字体、外部图片库或第三方文档预览服务。

## 容量和格式

单附件 50 MB，每活动最多 100 个附件；每批添加最多 200 MB。完整备份的附件原始总量上限 200 MB，导入备份最大 300 MB；大文件场景应使用专用后端。Word、Excel、PowerPoint、压缩包等可归档和下载，暂不内嵌解析；PDF 与音视频取决于浏览器格式支持。

## 开发与部署

直接托管 `index.html` 和 `assets/`，无 npm 安装或构建步骤。所有路径相对引用，适配 `/Activity-Log/` 子路径。

```sh
python3 -m http.server 8000
```

CI 会运行语法检查和真实 Chromium 端到端测试，保存测试结果与截图，然后部署到 GitHub Pages。首次启用 Pages 可能需要仓库所有者在 Settings → Pages 中选择 GitHub Actions；工作流不能绕过 GitHub 的管理权限。

## 维护约定

保持原文件完整，不把用户文件上传到公共站点。图片动画使用有界 DOM 卡片与 `requestAnimationFrame` 弹簧积分，只更新 transform/opacity，最多六层卡片。记录与附件在同一 IndexedDB 事务写入，失败不显示保存成功。完整备份导入校验格式并作为独立副本追加，不覆盖已有数据。
